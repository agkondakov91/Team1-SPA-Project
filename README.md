# Team1-SPA-Project

Это **учебный проект**, созданный в рамках практики командной разработки одностраничного приложения (SPA). Проект является **некоммерческим**, не нарушает авторские права и использует макеты исключительно в **ознакомительных целях** для образовательных задач. Все материалы, включая код и дизайн, предназначены только для обучения и не используются в коммерческих целях.

## Правила

- **Запрещено** пушить напрямую в ветку `main`.
- Изменения вносятся через feature-ветки, которые мержатся в `develop` после ревью тимлидом.
- Финальные изменения из `develop` вливаются в `main` через Pull Request (PR).
- Тимлид ревьюит все PR перед слиянием.

## Рабочий процесс

### Ветки

- `main`: Стабильная версия проекта (финальные релизы).
- `develop`: Промежуточная ветка для интеграции изменений из feature-веток.
- `feature/task-name`: Ветки для отдельных задач (например, feature/login-form).

### Работа с Git

1. Создайте ветку для задачи:

```
git checkout -b feature/task-name
```

2. Закоммитьте изменения:

```
git commit -m "Add feature description"
```

3. Запушьте ветку:

```
git push origin feature/task-name
```

4. Создайте Pull Request из `feature/task-name` в `develop`:

- В GitHub выберите `develop` как целевую ветку.
- Укажите Closes #issue_number для связи с задачей.
- Назначьте тимлида как ревьюера.

5. Тимлид ревьюит PR, мержит в `develop` или запрашивает правки.

6. После накопления изменений в `develop` тимлид создаёт PR из `develop` в `main`:

- Убедитесь, что develop протестирован (нет багов, всё работает).
- PR в `main` должен содержать описание всех влитых изменений.

7. После слияния PR в `main` обновите локальный репозиторий::

```
git checkout main
git pull origin main
git checkout develop
git pull origin develop
```

---

### Код-ревью

- Тимлид проверяет PR (из `feature/*` в `develop` и из `develop` в `main`).
- Убедитесь, что код читаем, нет багов, и он соответствует задаче.
- После одобрения PR мержится в **main**, feature-ветка удаляется.

### Канбан-доска

Используйте GitHub Projects для управления задачами:

- **To Do**: Новые задачи.
- **In Progress**: Задачи в работе.
- **Review**: PR на ревью.
- **Done**: Завершённые задачи.

Тимлид создаёт Issues, назначает ответственных и перемещает задачи по столбцам.

Team1-SPA-Project: Документация для колледжа

Описание проекта

Team1-SPA-Project — это учебное одностраничное приложение (SPA), разработанное студентами в рамках учебной практики для колледжа с целью освоения современных веб-технологий и командной работы. Проект основан на макете "Zero Design", предоставленном через Figma, и представляет собой демонстрационную платформу, включающую лендинги, страницы компании, CMS-разделы и утилиты. Сайт оснащён интуитивной навигацией через основное меню в шапке и бургер-меню для мобильных устройств, а также содержит кнопку "Buy Now" для симуляции покупки и форму подписки в футере. Дизайн адаптирован для различных разрешений экранов — от 321px (мобильные устройства) до 1280px (десктопы) — благодаря использованию медиазапросов и гибких макетов. Интерфейс включает плавную прокрутку, анимации при наведении (например, на кнопки и ссылки) и сеточную компоновку для отображения контента, что демонстрирует навыки создания удобного и эстетичного пользовательского опыта.

Назначение и функциональность

Проект создан как часть учебной программы колледжа для отработки навыков разработки веб-приложений. Он служит примером реализации адаптивного дизайна и базовой интерактивности, включая открытие/закрытие бургер-меню и отображение секций с информацией (например, #info1 и #info2). Хотя некоторые элементы, такие как JavaScript-логика, ещё не полностью реализованы, проект демонстрирует базовую структуру и готовность к дальнейшему развитию. Это позволяет студентам изучить процесс создания SPA и подготовиться к более сложным задачам.

Технологии

Для разработки используются передовые веб-технологии. HTML5 применяется для создания семантической структуры с использованием тегов, таких как, что улучшает доступность и совместимость с поисковыми системами. CSS3 реализует стилизацию с методологией BEM (например, card__title, button--active), обеспечивая модульность и переиспользуемость кода. Адаптивность достигается через единицы rem, em и проценты, а также с помощью flex и grid-сеток. Стили распределены по файлам: style.css содержит основные правила, bigsection.css управляет крупными секциями, burger.css отвечает за бургер-меню, header.css — за шапку, section.css — за информационные блоки, а global.css задаёт глобальные переменные (цвета, шрифты). Шрифт Jost подключён через fonts.css с локальными файлами .woff и .woff2, поддерживая разные веса (Regular, Medium, Bold), с возможностью использования Google Fonts как альтернативы. JavaScript применяется для обработки событий, таких как управление бургер-меню, хотя файл script.js пока пустой. API реализовано с помощью json-server, который имитирует серверные данные из файла db.json (например, список продуктов через GET /api/products). Разработка ведётся в Visual Studio Code с использованием Live Server для локального тестирования на порту 5500 и Node.js версии 22.12.0+ для управления зависимостями через package.json.

Структура проекта

Проект имеет чёткую иерархическую структуру. Папка docs содержит документацию (api.md и testing.md), images — графические активы (PNG, SVG, WEBP), public — основной файл index.html и папку img с изображениями, src — компоненты, стили (включая папку fonts с шрифтами), JavaScript-файлы (api.js, App.js, script.js) и серверные данные (db.json). Такая организация облегчает навигацию по проекту и его дальнейшую поддержку, что важно для учебных целей.

Рабочий процесс

Разработка осуществляется с использованием системы контроля версий Git. Используются ветки: main для стабильных версий, develop для интеграции изменений и feature/task-name (например, feature/login-form) для отдельных задач. Изменения вносятся через feature-ветки, проходят код-ревью тимлидом и мержатся в develop, а затем в main через Pull Request с указанием номера задачи (Closes #issue_number). Управление задачами осуществляется через Kanban-доску на GitHub Projects (https://github.com/users/agkondakov91/projects/4/views/1), где задачи распределены по статусам To Do, In Progress, Review и Done. Тимлид создаёт задачи, назначает исполнителей и отслеживает прогресс, что учит студентов дисциплине и командной работе.

Заключение

Team1-SPA-Project демонстрирует практическое применение веб-технологий и навыков командной работы, приобретённых в колледже. Проект готов к дальнейшему развитию и может быть использован как основа для более сложных заданий. Для получения дополнительной информации или помощи в доработке обращайтесь к тимлиду через GitHub.
